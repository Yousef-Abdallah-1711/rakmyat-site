# Known Issues and Production Decisions

- **Brand identity:** the source logo is identified as user-supplied, and its derived mark is used in the Iteck header/footer wordmarks. The Iteck light palette remains. No approved palette/type token sheet or logo/media license document was found.
- **Business copy:** bilingual positioning and a five-area service catalogue were adapted from owner-provided BDA materials. Obtain owner approval of public wording, scope, and operational claims before production.
- **Portfolio and media rights:** the owner confirmed all nine projects are personally owned and built, and all nine bilingual detail pages now present those projects. Permission to reproduce client names, third-party marks, course/product imagery, and other media visible in selected screenshots remains unverified. See the [project-by-project publication register](./phase-3.2/project-publication-register.json) before external use.
- **Limited case-study evidence:** Concord CRM and Product Scraper source repositories/docs were unavailable; their pages use text-led identity treatments and avoid detailed technical claims. Public project URLs in the register were observed in source review but not live-verified during Phase 3.2.
- **Contact:** the bilingual inquiry workflow, PostgreSQL schema, rate limits, admin dashboard, and durable email outbox are implemented. Local development now has PostgreSQL 17 on `localhost:5432` (database `rakmyat`), a `.env.local` with `DATABASE_URL`, `RATE_LIMIT_SECRET`, and `ADMIN_IP_ALLOWLIST`, and a provisioned local admin, so persistence and the admin dashboard run locally. `SMTP_*` keys are present in `.env.local`, but live email delivery has not been verified. Contact/domain candidates from BDA remain unpublished. See the [Phase 3.8 setup and QA](./phase-3.8-contact-navigation/README.md).
- **Domain and SEO:** no production domain is configured. Canonical and absolute Open Graph image URLs are omitted until `NEXT_PUBLIC_SITE_URL` is set; the sitemap has no absolute project entries before then.
- **Arabic review:** Arabic routes render RTL and have localized copy. Cairo (variable, 200–900) and Tajawal (400, 500, 600, 700) are self-hosted as WOFF2 under `public/fonts/`, declared in `public/assets/css/lib/cairo.css` and `tajawal.css`, and preloaded for the AR locale. No Google Fonts runtime request is made. No licence file for these fonts is in the repo; add one next to the WOFF2 files. New Arabic copy needs professional proofreading.
- **Legacy Arabic font remnant:** `public/fonts/NotoSansArabic-Variable.woff2` and `public/assets/css/lib/noto-sans-arabic.css` still exist, and `public/assets/css/style.css` still lists "Noto Sans Arabic" as a fallback in its font stack. Remove the fallback and the unused files once the Cairo/Tajawal rollout is confirmed.
- **Visual and interaction review:** Phase 3.2 captured all 120 English/Arabic route and viewport states with zero broken images, document overflow, visible heading clipping, console errors, or failed local requests. Automated interactions cover filters, navigation, lightbox, mobile menu/focus, service carousel, scroll control, form constraints, and metadata. See the [Phase 3.2 report](./phase-3.2/implementation-report.md); these checks are not cross-browser or manual accessibility certification.
- **Functionality:** portfolio filters and project routes work. The retired Notero route remains unpublished/404. The scope table is informational and not a quote; the workflow panel is illustrative, not a testimonial or case study. Contact backend code still needs PostgreSQL, a first admin account, and SMTP setup before live operation.
- **Source and rights:** selected portfolio screenshots were copied from BDA for local review; written media permissions remain pending. Original theme media and Font Awesome Pro files still need applicable redistribution-rights review. No vendor private source, PHP backend, or CMS is present.
- **Accessibility and release:** no deployment occurred. Manual contrast, screen-reader, 200% zoom/reflow, cross-browser, animation timing, and final brand/copy review remain open.
- **Blog body HTML is not sanitised:** TipTap output is stored in `blog_posts.body_en` and `body_ar` and rendered with `dangerouslySetInnerHTML` in `components/sections/BlogPostSection.tsx`. This is safe only because authorship is admin-only. Add an HTML sanitiser (allowlist-based) before any non-admin author, import, or write path is added.
- **Blog changes can take up to one hour to appear publicly:** the archive and post pages use `revalidate = 3600`, and `GET /api/blog/posts` and `GET /api/blog/filters` send `s-maxage=3600`. Admin saves do not call `revalidatePath` or `revalidateTag`. Add on-demand revalidation to the `/api/admin/blog/*` write handlers.
- **`portfolio-media.test.ts` fails (17 vs 19 gallery images):** `node --import tsx --test tests/portfolio-media.test.ts` gives 1 pass and 1 fail. The failing case, "every case-study gallery image has explicit, existing source metadata", asserts `17 !== 19`. The test file is not modified in the working tree and the cause has not been investigated. It is unrelated to the blog work.
- **Media uploads are local static files:** uploads are saved to `public/uploads/images/` and `public/uploads/videos/` and served as static files. There is no CDN or object storage yet (planned). `public/uploads/` is not in `.gitignore`, so uploads can be committed unless that changes. No volume for that path appears in the compose files, so uploads are lost when a container is replaced.
- **Admin sign-in must use `localhost`:** use `http://localhost:5175/admin/login` consistently. The origin check in `lib/server/security.ts` treats `127.0.0.1` and `localhost` as the same origin, but session cookies are host-scoped, so a session started on one host is not sent to the other. `ADMIN_IP_ALLOWLIST` in `.env.local` and `playwright.admin.config.ts` both use `localhost`. The comment in `playwright.admin.config.ts` says `127.0.0.1` origins are rejected, which the current origin check does not do, so that comment may be stale.
- **`ADMIN_IP_ALLOWLIST` is missing from `.env.example`:** the variable is documented in the README and set in `.env.local`, but not listed in `.env.example`, so new environments will not pick it up.
- **Migration 0003 has no rollback file:** `0002` ships `0002_bounded_outbox_retries.down.sql`, but `0003_blog.sql` has none. Reverting it means dropping the blog tables manually.
