# 06 — Admin and authentication

Admin accounts are created explicitly with the interactive `scripts/create-admin.ts` tool. It requires a terminal, hashes passwords with scrypt, does not echo or persist the password, and refuses to overwrite an existing email. There is no default production administrator. The Compose admin tool uses the application DB role and private database network; run it only after migrations and with the approved administrator identity. The local `admin:create` command now uses the same Node type-stripping execution mode as the production tool, avoiding the workspace's CommonJS/top-level-await transform failure.

Sessions use random bearer tokens stored as SHA-256 hashes, HTTP-only, SameSite Strict cookies, the Secure flag in production, and a 12-hour expiry. Login is rate-limited by client and account identifiers. Logout and inquiry mutations require same-origin requests. Admin pages are forced dynamic; sensitive APIs require server-side session checks and `private, no-store` responses. Submitted inquiry text is rendered as text by React, not injected HTML.

The inquiry API now returns a maximum of 25 records per page with validated page bounds, filtered result counts, deterministic ordering, and private no-store headers. The interface resets to page one when filters change and provides keyboard-accessible previous/next controls. A disposable Phase 4.9 smoke passed admin login, page 1/page 2 pagination over 26 synthetic rows, status/private-note update, and logout revocation. Production account provisioning, recovery contact, and access policy remain owner-controlled.
